context_summary: |
  **DEFERRED from MVP** per user direction on 2026-05-25. Reason: dashboard prerequisites (Apple Developer Program enrollment, App Store Connect Paid Apps agreement, Google Play merchant account, GCP project + Pub/Sub for Google RTDN, sandbox tester provisioning on both stores) plus the slow provider-sandbox feedback loop add friction that is incompatible with rapid MVP iteration. This PRD is intentionally absent from the thin `implementationplan.md` index so that `/implement-phase 13` cannot accidentally dispatch it during MVP work. The user will move this file out of the active `implementationplan/` folder manually; restore it (and add an index entry) when MVP is shipped and premium becomes a priority.

  **Ordering constraint at un-defer time:** This phase MUST execute BEFORE phase 6. The premium-tier model is enforced at three layers — PreTokenGeneration injects `custom:subscription_tier` into the access token (phase 4 wires the Lambda; this phase extends it), the API gates premium-only endpoints by reading the JWT claim, and the data layer reads `users.subscription_tier` directly when the JWT claim is insufficient (e.g., deck-boost ranking has to read other candidates' tiers, not just the requester's). Phases 6 (rate limits, friend requests) and 7 (deck, swipes, see-who-liked-me) need both the JWT claim and the denormalized column from day one. Shipping phase 13 first means those phases never need a "premium retrofit" pass.

  **Scope is backend-only.** The React Native app (separate project, not in this workspace) integrates StoreKit 2 / Play Billing Library, surfaces the paywall, and POSTs receipts / purchase tokens to the endpoints this phase builds. The app-side work lives entirely in that project — this PRD ships only the AWS infrastructure, Lambdas, schema, and validation endpoints.

  **Architectural shape (locked from the 2026-05-25 brainstorm):**
  - **Two tables, both append-only.** `subscriptions` is the subscription state machine — one row per subscription period (a renewal opens a new row, a cancellation sets `ended_at`); current state = `WHERE user_id=X AND ended_at IS NULL` (at most one). `purchases` is the financial ledger — one row per provider-emitted billable event (initial, renewal, refund, chargeback, proration adjustment) with `provider_event_id UNIQUE` for webhook idempotency. Append-only keeps the audit trail intact for refund/chargeback disputes and for analytics. Current-state queries hit the partial index on `subscriptions(user_id) WHERE ended_at IS NULL`.
  - **Denormalized cache.** `users.subscription_tier text NOT NULL DEFAULT 'Free'`. NOT optional — deck-boost ranking (phase 7) reads tier per-candidate inside the SQL query; the JWT claim only carries the requester's tier. Single-writer pattern: only the billing webhook handlers update this column. Writes are inside the same transaction that inserts the subscription period, so the cache and the source of truth never diverge.
  - **JWT claim for hot-path gates.** PreTokenGeneration Lambda (built in phase 4) is extended here to embed `custom:subscription_tier` (read from `users.subscription_tier`). Authenticated requests gate premium endpoints off the claim with zero DB hits. ~1-hour staleness (token lifetime) is acceptable — a user who just upgraded sees premium features after their next token refresh; this is industry-standard behavior.
  - **Provider-agnostic schema.** `provider text` discriminator with values `'apple_iap' | 'google_play'` (extensible to `'stripe'` if web checkout is ever added). `raw_provider_payload jsonb` stored on each `purchases` row for forensic debugging without re-querying the provider.
  - **Two tiers only:** `'Free'` (default) and `'Premium'`. No tier-laddering at MVP — keeps the migration, the JWT claim values, and the frontend paywall trivial.
  - **Two billing periods:** monthly and annual. Encoded in `subscriptions.billing_period text CHECK (billing_period IN ('monthly', 'annual'))`.
  - **Two providers at MVP:** Apple IAP and Google Play Billing. Stripe is intentionally excluded — Apple/Google App Store policy REQUIRES first-party IAP for in-app digital goods on iOS/Android (30% revenue share). Stripe / web checkout is only viable if a web app ships later; out of scope.

  **In-phase deliverables:** schema (1 migration adding 2 tables + 1 column + indexes), shared billing layer (signature verification + provider API client wrappers), Apple IAP webhook + receipt-validation endpoint, Google Play RTDN webhook + token-validation endpoint, GCP Pub/Sub infrastructure (Terraform GCP provider), PreTokenGeneration claim extension, `GET /v1/me/subscription` status endpoint, IAM roles + Secrets Manager wiring for both providers, sandbox-validated end-to-end test runbook, and the dashboard-prerequisite human checklist that gates testing (story 13.0).

  **Explicitly out of phase 13** (deferred to consuming phases when premium features ship): deck-boost ranking SQL (phase 7), friend-request rate-limit tier multipliers (phase 6), swipe-quota enforcement (phase 7), `GET /v1/me/likes` "see who liked me" endpoint (phase 7), promo codes, gift subscriptions, Stripe / web checkout, family-plan sharing.
